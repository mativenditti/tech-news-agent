02 / 07

Stack

Sobre qué está construido

LangGraph + LangChain
El corazón: un grafo stateful con nodos, tools, memoria por conversación e interrupts. Define el flujo entrada → guardrails → agente ⇄ tools.
Gemini 3 Flash
El LLM que razona y decide qué tool usar, vía langchain-google-genai. Modelo “thinking” con budget de razonamiento ajustado por caso de uso.
Tavily
Búsqueda web en tiempo real (langchain-tavily): la fuente de las noticias frescas.
Postgres + pgvector
El vector store del RAG. Persistente y compartido, con embeddings reales de Google (gemini-embedding-001).
LangServe + FastAPI
Expone el grafo por HTTP: /chat, /chat/resume, /briefing, más variantes SSE en streaming.
LangSmith
Tracing y observabilidad de cada ejecución del grafo — sin una línea de código, sólo variables de entorno.
03 / 07

Tools

Las herramientas del agente

El LLM decide cuándo llamarlas. Dos son de libre uso; la tercera está gateada por un humano.

web_search

Buscar en la web

Trae titulares y detalles actuales vía Tavily. Se usa para noticias recientes o pedidos concretos (“el repo de X”). Devuelve fuentes con link.

rag_search

Recuperar lo ya visto

Busca en el corpus propio de noticias ya ingeridas, para profundizar o citar fuentes previas sin volver a la web.

send_email_report · HITL

Reporte por email

Prepara el reporte y pausa pidiendo confirmación humana. Sólo si se aprueba, envía por SMTP.

Detalle: cada web_search que trae artículos los ingiere automáticamente en el RAG. Buscar y recordar son el mismo loop.

04 / 07

RAG

Memoria de noticias, no sólo búsqueda

  • Postgres + pgvector como vector store: real, persistente y compartido — no un archivo local que se pierde.
  • Embeddings reales de Google (gemini-embedding-001, 3072 dims) para búsqueda semántica de verdad.
  • Ingesta idempotente: id estable por URL → reingerir el mismo artículo hace upsert, no duplica.
  • Loop cerrado: lo que web_search trae queda indexado y rag_search lo recupera después.
psql · tech_news

SELECT title, vector_dims(embedding)
FROM langchain_pg_embedding;

Por qué así: un agente que lee la web necesita recordar para profundizar y citar sin re-buscar. pgvector lo hace compartible entre procesos y deploys, con SQL estándar y sin vendor lock-in.

05 / 07

Human-in-the-loop

Un humano antes de actuar sobre el mundo

Buscar o recordar es reversible. Mandar un email no. Por eso esa acción pasa por una aprobación humana.

usuario→ guardrails→ agent · Gemini⇄ tools→ send_email → interrupt⏸
1 · pausa

El grafo se detiene

La tool llama a interrupt() de LangGraph. El estado queda guardado en el checkpointer por thread_id.

2 · propuesta

Se muestra el borrador

La API devuelve type: approval con el destinatario, asunto y cuerpo del reporte para revisar.

3 · decisión

Aprobar o rechazar

POST /chat/resume reanuda el grafo. Sólo con approve se envía; si no, se cancela.

La clave: el interrupt vive dentro de la tool y el estado persiste, así la pausa sobrevive entre requests HTTP. El agente nunca promete “ya lo mandé”.
